# Continuous Improvement

1. Read `.agent-engineering/core/continuous-improvement.md` and the project's improvement backlog.
2. Look for repeated failures, instruction ambiguity, missing tests, brittle workflows, avoidable context cost, and mismatches between intended and actual agent behavior.
3. Support every finding with reproducible evidence, not a general preference.
4. Rank by impact, likelihood, cost, and confidence.
5. Prefer deterministic tests, linters, scripts, or clearer local documentation over vague global instructions.
6. Distinguish project-specific improvements from changes to the reusable engineering system.
7. Propose changes; do not silently modify canonical standards or weaken safety controls.
8. Record accepted, rejected, and deferred proposals with rationale.
